You don't need this page to use glass, but it explains why the rest of the docs say what they say.

Why not plain CSS

CSS can blur what is behind an element with backdrop-filter, and that is all. It can't move pixels, so it can't bend light. To bend light you need a program that runs for every pixel, and in a browser that is a shader on the graphics card. WebGL is the way to run one.

The catch

For security reasons a page can't read its own pixels. So glass can't simply look at what is behind it. It has to find the source: an image, a video, a canvas or a solid colour. That is why Backdrop matters, and why text behind glass needs extra work.

What happens in a frame

First glass finds its source and uploads it to the graphics card. Then the shader works out the curved edge of your shape and, for each pixel, where the light would come from. It reads that spot, splits the colours, adds frost and the highlight. The result is drawn into a canvas inside your element.

Why it stays fast

The whole page shares one WebGL context, and a frame is drawn only when something changes. If nothing moves, the graphics card does nothing.
